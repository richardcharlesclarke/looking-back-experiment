# Study Two questionnaires — durable server storage, 10 September 2026

This release adds role-specific questionnaire pages to the existing experiments hub. It does not change Study One's proxy, hosted service, start command, instrument or records.

- `/study-two/speaker/before` and `/study-two/speaker/after`
- `/study-two/audience/before` and `/study-two/audience/after`
- `/study-two` is a speaker-before entry for convenience.
- `/study-guides/study-one` and `/study-guides/study-two` are separate researcher guides.
- `/study-two/review` holds setup, all four direct entry links, preserved walkthroughs and CSV/JSON downloads. Participant pages do not link to it or include its controls.

Publication is for Richard's inspection, with proper server-side persistence. Participant distribution is not authorised. New records are explicitly marked isTest=true while panel details and participant information remain unfinished. `/study-two/api` validates requests and proxies over the private Railway network to a dedicated service, `study-two-store`, with its own `/study-two-data` volume. No Study One database, volume or service is shared or changed. Protected `/study-two/api/admin` supplies server exports and panel setup using the hub's existing authenticated admin session; it fails closed if production admin credentials are missing. Exports retain exact question snapshots, scales, panel/role/person IDs, missingness, draft revisions and server timestamps, excluding access keys and their hashes. Earlier `study-two-review-v1` browser-only records are preserved separately and are not silently imported.

Each person receives a UUID and a separate cryptographically random 256-bit access key. Only the SHA-256 key digest is stored. Return URLs carry the key in a fragment, which is not sent in HTTP request URLs; API requests use JSON over HTTPS. The same private link reopens progress across browsers. Role and instrument are bound to the server record; the after form requires the completed before response. Panel snapshots and both questionnaires are frozen at creation. Continue/Back save drafts on the server using optimistic revision checks; stale changes are rejected. Equal retries return the saved result, and completed answers cannot be overwritten. Custom panel IDs are content-derived, stable across people with identical panel configuration. The example claim and Speaker A/B/C labels are placeholders; selection, consent, allocation and delivery must be settled before fieldwork.

The new instrument is `study-two-review-v1-2026-09-10`. It deliberately revises the earlier v0.1 bank under Richard's request for a sensible draft, rather than silently relabelling the old responses. Five common speaker items replace eight; the same topic position/confidence/understanding measures and other-speaker position predictions repeat at both waves. With three speakers: 11 before and 17 after, including optional writing. Audience: 5 before and 10 after. Agreement and ability use item-appropriate continuous 0–100 labels; topic scales retain 0–10. The actual Study One `ContinuousOrb` and participant CSS are reused with local instrument imports. No continuous answer is converted to a seven-point score.
